# Competitor Benchmark

Execute an objective market and competitive analysis grounded exclusively in verifiable, live web and repository data.

## Procedure

1. **Understand the Subject Product**:
   - Inspect the target project's capabilities, target audience, stack, and core workflows before searching.
   - Define 3 to 5 functional axes to compare against competitors (e.g., input formats, output fidelity, local/privacy execution, UX, domain specialization).

2. **Discover Real Competitors**:
   - Search GitHub, official product sites, technical blogs, and community discussions within the requested market/language scope.
   - Filter out dead or obsolete software unless explicitly relevant as a historical baseline; prioritize actively maintained tools and modern architectures.

3. **Collect Verifiable Adoption & Recency Metrics**:
   - For every open-source competitor, retrieve and report actual figures from search results:
     - Repository URL
     - GitHub stars (approximate or exact as observed)
     - Last commit / latest release date
     - Commit / maintenance cadence and contributor activity
     - Tech stack and architecture (CLI, desktop, web, WASM, cloud, AI-assisted, etc.)
   - For commercial/closed-source tools, report pricing model, platform, update recency, and user traction signals.
   - Never fabricate or extrapolate star counts, dates, or URLs. If a metric cannot be verified, state it explicitly as unverified.

4. **Analyze Gaps, Trends & Threats**:
   - Compare strengths and weaknesses of each hard competitor against the target project.
   - Identify current industry trends (modern browser APIs, local-first/WASM, AI-assisted workflows, UX expectations, format standards).
   - Pinpoint unserved pain points and where the target project risks falling behind or holding an unfair advantage.

5. **Formulate Strategic Recommendations**:
   - Deliver concrete, prioritized recommendations on positioning, differentiation, and roadmap focus.
   - Highlight open strategic questions or trade-offs that require the stakeholder's decision.
